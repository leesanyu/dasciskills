# Feature：工作表与字段选择体验

- 标识：`table-selection-experience`
- 状态：已完成；T1–T3 已依次验收，无旧接口兼容层。
- 适用对象：在 CSV / Excel 中选择工作表及两列的用户，尤其是 sheet 多、列多或列名不直观的场景。
- 共享契约：[多方法统计分析](feat-relationship-statistics-coverage.md) 的 ColumnSpec、类型覆盖、有序映射和 MethodPlan。

## Non-Goals

- 不建设独立 Web 应用，不提供文件上传服务、跨 sheet Join 或多字段批量分析。
- 不自动修改源 Excel，不猜测多行表头、合并单元格或前置说明行，不静默换表/换列。
- 不依赖某一个宿主的专属提问工具；不为选择交互新增运行时依赖。

## 业务意图与现状

让用户清楚看到正在选择哪个文件、工作表和字段，能用名称或编号完成选择，并在类型不符或输入错误时只修正受影响的步骤。

实施前，skill 已要求列出 sheet 和字段，但字段选择无论是否已提供都必须再次确认，长表必须一次铺开全部内容，两列分别询问且都包含同一列；返回字段已有 sample 却未充分用于选择界面。脚本缺少稳定 sheet 编号、原始列头映射和明确的可选状态。

## 核心数据契约

| 对象 | 字段与语义 |
|---|---|
| SheetOption | `index`：工作簿顺序的 1-based 编号；`name`；`rows/columns`：已用区域估计，可为 null；`state`；`selectable` 与 `reason` |
| ColumnOption | 基于当前 profile 提供 `original_name`、`display_name`、`index`、`sample`（最多 3 个截短示例）、`inferred_kind`、`suggested_kind`、`selectable`、`reason`；统计 kind 使用共享契约 |
| Selection | 文件路径、精确 sheet 名、两列位置/原名/显示名、确认的有效类型和 ordinal 顺序、`methods`（默认 auto）、`confirmed`；确认指用户明确指定或对摘要确认 |
| InteractionState | `needs_file → needs_sheet → needs_columns → needs_semantics/needs_confirmation（按需）→ ready`；错误附当前步骤与可重选对象 |

`inspect` 输出字段概况与选择元数据；`analyze` 继续使用名称或 `--col1-index/--col2-index`。同一选择器同时传名称和编号时须解析为同一列，否则报错，不默默偏向其中一个。重复/空白列头按原始物理位置区分，不能依赖读取器自动生成的后缀反推原列。

编号始终对应工作簿/源表顺序，分页、搜索或过滤不能重新编号。用户选择绑定精确名称和物理列位置；切换文件/sheet 后清除不再适用的字段选择。

当前接口：`inspect --input FILE [--sheet NAME|--sheet-index N] [--page N] [--search TEXT] [--all-columns] [--exclude-index N]` 提供目录/预览；`select --request JSON_FILE` 提供交互状态，ready 后返回精确 `analysis_args`。
选择请求由模型维护，含前次 `state`、本轮 `action`、`view` 与实际 `host` 提问能力；状态保存未绑定的已给选择、两个独立字段槽位和摘要确认范围。仅完整初始输入 `explicit=true` 或用户确认当前摘要时 ready，默认高亮不提交；未 ready 的 analysis_args 为 null。JSON 只用于模型调用，不要求用户输入。实现不保留旧选择契约的适配层。


## 选择行为契约

### 文件与 sheet

- 未给文件时询问路径；不扫描目录猜文件。CSV/TSV 跳过 sheet 步骤。
- Excel 首次展示“文件名、sheet 数量、当前选择状态”；sheet 列表含编号、完整名称、约行×列、隐藏状态与备注。行数注明可能包含表头和格式范围，不伪装成有效样本量；未知显示“未知”。
- 未指定 sheet 时，多个 sheet 用一次明确选择完成；只有一个也展示其信息并接受用户确认。已给出且唯一匹配的 sheet 视为明确选择，直接预览，不重复询问。
- 空表不可选；隐藏表可显式选择并保留提示，不因隐藏而代选。仅凭格式化已用区域不能断言非空或空表，未知状态在打开后验证。
- 列表≤20 项时展示全部；超过 20 项分 20 项一页，给出总数、当前范围及“下一页/按名称查找”。全部候选可访问，不能仅暴露前几项。
- 名称/编号都可选择；编号按编号选择，名称按名称选择，有歧义时要求 `#编号` 或明确名称，不猜。不存在或大小写匹配不唯一时给候选并留在当前步骤。

### 字段预览与选择

- 打开 sheet 后，先显示 sheet 名、有效数据行数、列数和前 5 行预览；宽表预览只显示当前页字段并说明范围。
- 字段目录含编号、完整名称、推断类型、缺失率、唯一值数、最多 3 个截短示例和不可选原因；≤20 列全部展示，更多字段分页或按名称搜索，并可请求完整列表。完整列名不能仅用省略号替代。
- 默认一次询问两列，示例“回复 `#2, #7` 或 `年龄, 收入`”；宿主支持多选时限制恰好两列。若使用两次单选，第二次排除第一列。
- 支持带空格/标点的精确名称；名称含分隔符、重名或空表头时引导使用编号。不能仅靠按逗号拆分名称导致选错列。
- ID/空列/常量/高基数文本显示原因并阻止直接分析，仍留在目录可见；疑似 ID 或数字分类可确认业务语义并走类型覆盖，不静默丢弃。
- 用户可在此修正有效类型；选 ordinal 时展示实际水平并要求业务顺序。只追问确实缺失的类型信息，传给脚本的映射必须与用户确认一致。

### 确认、纠错与工具适配

- 用户已明确提供有效文件、sheet 和两列时，展示选择摘要并直接执行；仅缺少或有歧义的输入需要提问。显式指定的语义信息不重复确认。
- 通过列表交互选列后，展示“文件 → sheet → 字段 A〔有效类型〕× 字段 B〔有效类型〕→ 多方法候选及分析问题”，对尚未确认的组合用一次“开始分析 / 修改选择”确认；不再逐列确认。
- 默认按 auto 方法集合分析，无须用户逐个选择统计方法；可自然语言指定方法子集，由 skill 转成契约标识。选择摘要区分候选与实际适用方法，不承诺一定有两种有效检验；执行后显示不适用原因。
- 出错只返回当前步骤：同列/无效列只改字段，语义缺失只改类型，sheet 改动才重新选字段；合法且仍适用的既有选择保留。未满足选择条件不运行统计。
- 使用宿主实际可用的提问工具；工具缺失、候选数量或单选数量受限时，用编号列表加普通文本提问，等待明确答复。提问 UI 的默认高亮不算用户确认。
- 完整选择过程不需要用户输入 Python 命令、列转义语法或内部 JSON；ordinal 顺序可用“低 → 中 → 高”自然语言表达，由 skill 转成契约参数。

## 主链路

1. 文件已给、sheet/字段未知 → 选 sheet → 看预览与字段目录 → 一次选两列 → 必要时修正语义 → 确认摘要 → 调用分析。
2. 用户已给有效文件、sheet 和两列 → 检查并展示摘要 → 直接分析；遇到歧义时只补齐相应步骤，修正后继续。
